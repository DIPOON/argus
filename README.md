# ARGUS

브라우저에서 플레이하는 1–4인 협동 PvE 프로토타입. C# 서버가 이동, 탄환, 피해, 자원, 증원, 시야, 임무 결과를 계산하고 TypeScript/PixiJS 클라이언트가 입력과 화면을 담당한다.

## 실행

필요 환경: .NET 10 SDK, Node.js 22.12 이상. 서버는 Linux에서 실행할 수 있다. 데이터베이스나 Unity는 필요하지 않다.

저장소 루트에서:

```bash
npm --prefix client ci
npm --prefix client run build
dotnet run --project server/Argus.Server --urls http://127.0.0.1:5077
```

브라우저로 <http://localhost:5077>에 접속한다. 호출명, 주무기, 보조 장비, 패시브를 고르고 **새 작전 시작 → 캠프 선택 → 5초 후 투입**을 누르면 시작한다. 투입 전에 지도에서 다른 빈 지면을 골라도 된다. 선택하지 않으면 계속 대기한다.

친구는 같은 서버 주소에 접속한 뒤 6자리 방 코드를 입력한다. 다른 PC와 시험할 때는 서버를 `--urls http://0.0.0.0:5077`로 실행하고 해당 PC가 접속 가능한 서버 주소를 사용한다. 방 코드만으로 다른 PC의 localhost에 연결되지는 않는다.

WSL의 Ubuntu 24.04에 .NET SDK가 없다면 Ubuntu 터미널에서 설치한다. Windows PowerShell에서 실행하려면 Windows용 SDK가 별도로 필요하다.

```bash
sudo apt update
sudo apt install -y dotnet-sdk-10.0
```

클라이언트 수정 중에는 서버를 켜 둔 채 별도 터미널에서 `npm --prefix client run dev`를 실행하고 <http://localhost:5173>을 사용한다. Vite가 API와 WebSocket을 5077로 전달한다.

## 조작과 첫 임무

| 조작 | 동작 |
| --- | --- |
| WASD / 방향키 | 이동 |
| 마우스 이동 / 왼쪽 버튼 유지 | 조준 / 사격 |
| R | 선택한 무기 재장전, 빈 탄창은 자동 재장전 |
| G | 선택한 보조 장비 사용: 수류탄 투척 / 조준 방향 가까이에 터렛 설치 |
| M | 전체 지도 전환 |
| 보급품에 접근 | 체력·수류탄 보충 또는 부목표 회수 |

적 시설 3곳을 파괴한 후 남쪽 탈출 구역에 한 명 이상이 20초 동안 머물면 팀이 성공한다. 구역이 비면 탈출 진행도가 서서히 감소한다. 부목표 보급품 2개는 선택 사항이다. 주목표와 부목표는 한 구역에 모여 있다.

- 주무기는 소총·산탄총·관통총 중 하나, 보조 장비는 수류탄·터렛 중 하나를 고른다. 모든 주무기의 예비탄은 무한이다.
- 패시브: 체력 130 또는 기본 체력 100 + 이동속도 22% 증가. 첫 투입 후에는 변경할 수 없다.
- 아군 사격과 수류탄 자해가 있다. 벽은 탄환과 폭발을 막고 파괴할 수 있다. 맵 테두리는 파괴되지 않는다.
- 최초 투입·난입·사망 후 증원 모두 위치를 확정한 뒤 5초 준비한다. 기본 무적 시간은 없다.
- 살아 있는 대원이 한 명도 없으면 즉시 실패한다. 증원 중인 대원이나 아직 투입하지 않은 난입자는 전멸을 막지 못한다. 솔로는 한 번 사망하면 실패한다.
- 사망 후 무제한 증원이 가능하며 체력·탄창·수류탄은 초기 상태로 복원한다.
- 최초 투입 완료부터 10분마다 모든 생존 대원에게 60 → 120 → 240 … 피해를 준다. 캠프에서도 받으며 참가·재접속으로 타이머가 초기화되지 않는다. 10분 임무 길이는 향후 조정할 목표다.

### 장비 조합

| 주무기 | 탄창 / 재장전 | 특성 |
| --- | --- | --- |
| 돌격 소총 | 30발 / 2초 | 24 피해, 안정적인 연속 사격 |
| 산탄총 | 6발 / 2.6초 | 한 발에 산탄 7개, 각 12 피해. 부채꼴로 퍼지고 사거리 300 |
| 관통총 | 8발 / 2.8초 | 60 피해, 일직선 적 최대 3마리 관통. 벽·시설·아군·터렛에서 멈춤 |

수류탄은 3개를 가지고 투입하며 보급으로 보충한다. 터렛은 조준 방향 44만큼 앞의 빈 지면에 **G**로 설치한다. 초록 설치 표시는 가능 위치, 빨간 표시는 불가 위치다. 터렛은 체력 100, 사거리 360, 최대 가동 45초이며 재설치 대기 시간은 20초다. 플레이어당 한 기만 유지하고 새로 설치하면 이전 기체를 교체한다. 수치는 플레이 실험을 위한 초깃값이다.

터렛은 추가 시야를 주지 않으며, 분대 시야와 자신의 사선이 모두 확보된 적을 자동 공격한다. 터렛의 탄환도 소유자를 포함한 아군에게 피해를 주고, 터렛 자체도 적·아군 탄환과 폭발에 파괴된다. 터렛 바로 뒤에서 사격하면 자신의 탄환이 터렛에 맞는다. 적은 가까운 터렛도 공격한다.

첫 투입 후 장비는 고정된다. 증원하면 선택했던 무기의 탄창과 보조 장비가 초기 상태로 복구된다. 사망 전 터렛은 수명이 남아 있으면 유지되지만 새 설치로 교체되므로 누적되지 않는다. 보급은 체력과 수류탄을 채우며 터렛 재설치 대기 시간을 초기화하지 않는다. 재접속은 기존 장비·탄약·터렛·대기 시간을 유지한다.

## 연결과 시야

각 탭은 서버가 발급한 비밀 복구 토큰을 `sessionStorage`에 보관한다. **같은 탭 새로고침**은 기존 대원으로 복귀한다. 새 탭을 주소창에서 열면 별도 게스트로 참가할 수 있다. 탭 복제는 브라우저에 따라 세션이 복사되어 기존 대원의 연결을 교체할 수 있다.

연결이 끊기면 이동·사격 입력을 멈춘다. 캐릭터는 피해를 받을 수 있는 상태로 120초 유지되고, 그동안 재접속하면 체력·탄약·사망·증원 진행을 그대로 이어받는다. 120초가 지나면 자리를 해제한다. **작전에서 나가기**는 복구 정보를 지우므로 새 대원으로 참가한다. 이전 자리는 같은 유예 기간 이후 해제된다.

팀의 생존 대원과 캠프가 확보한 시야를 합친다. 숨겨진 적, 탄환, 수류탄, 효과는 서버에서 필터링한 뒤 직렬화한다. 맵 구조, 벽의 파괴 상태, 목표·보급 위치 및 목표 진행은 공개 정보다. 투입 위치를 선택해도 새 시야는 생기지 않는다.

입력 자동화 차이 자체를 없애지는 않는다. 서드파티 클라이언트가 따라야 할 [통신 규격](docs/protocol.md)을 제공한다. 인증 없는 게스트가 토큰을 버리고 새 신분으로 접속하는 문제는 같은 사람인지 판별할 수 없다.

| `client/src/main.ts` | 참가·조작·HUD·재접속 |
| `client/src/world.ts` | 게임 렌더링, 보간과 이동 예측 |

세부 요구와 사용자의 결정을 [요구사항 기록](docs/requirements.md)에 보관한다. 임시 수치는 요구사항과 구분한다.

## 검증

첫 실행 환경의 결과와 한계는 [검증 기록](docs/verification.md)에 정리했다.

서버 검증은 외부 테스트 패키지 없이 실행하는 결정적 시뮬레이션 검사다. 실패하면 종료 코드 1을 반환한다.

```bash
dotnet run --project tests/Argus.Server.Tests
npm --prefix client run build
```

실제 브라우저와 통신 테스트는 서버 실행 후:

```bash
cd client
npx playwright install --with-deps chromium
npm run test:e2e
```

Playwright는 브라우저 탭 4개로 참가·재장전·새로고침 복구를 확인한다. 탭마다 별도의 게스트 토큰을 사용한다. 별도 WebSocket 클라이언트로 진행 중 난입, 위치·탄약·체력 위조, 잘못된 방향 입력, 재사용 입력, 잘못된 복구 토큰, 연결 교체, 5인 참가도 검사한다. 공개된 투입·사격 명령만 쓰는 자동 분대로 시설 파괴부터 실제 탈출 성공까지 확인한다.

## 운영 범위

Docker 설정은 `docker compose up --build`로 로컬 5077 포트에 노출하도록 작성했다. 현재 작업 환경에서는 Docker Desktop의 WSL 연동이 없어 이미지 빌드를 검증하지 못했다.

초기 구현은 메모리 기반 단일 서버다. 서버 재시작 시 방과 복구 토큰이 사라진다. 보상·계정 성장·영구 저장은 없다. 방은 최대 32개, 방당 적은 최대 180개로 임시 제한했다. 이는 부하 검증을 통과한 동시 운영 규모라는 뜻이 아니다. 클라이언트는 보이는 적을 모두 그리다가 FPS가 낮으면 가까운 적부터 표시 수를 줄인다. 서버 판정은 계속 진행된다.

서버 실행 주기는 목표 30Hz, 상태 전송은 약 10Hz다. 시뮬레이션은 서버 경과 시간으로 진행한다. 클라이언트는 화면의 이동을 예측하고 서버 위치로 보정한다. 하드웨어 WebGL을 사용할 수 없으면 PixiJS의 Canvas 렌더러를 사용한다. 브라우저 통합 테스트는 이 2D 대체 경로에서 실행한다. AI는 단순한 격자 경로 탐색이며 적끼리의 충돌은 생략했다. 사운드와 정교한 밸런스는 아직 없다.

GKE 배포 전에는 방의 프로세스 배정·연결 라우팅, 종료 중인 서버의 신규 참가 차단, 관측·부하 검증을 추가해야 한다. 현재 서버를 여러 복제본으로 올리면 방 상태가 공유되지 않으므로 단일 인스턴스로 시작한다. 공개 서비스에서는 HTTPS/WSS와 운영용 접근·남용 방지를 구성한다.
