# Argus 요구사항

마지막 갱신: 2026-10-05. 사용자와 요구사항을 맞추는 중이며, 아래의 제안은 확정된 결정과 구분한다.

## 목표와 우선순위

- 실제로 플레이할 수 있는 게임 하나를 완성한다.
- Veritas에서 기반 기술을 직접 만드는 경험을 중시했던 것과 달리, Argus는 게임 완성 속도를 우선한다.
- 사용자의 목표 직무는 게임 서버 개발자다. C# 사용을 선호할 수 있으며 Linux 서버를 원한다.
- 기존 엔진, 통신 라이브러리, 데이터베이스를 사용할 수 있다.
- 로드아웃 간 정교한 밸런스는 플레이 가능한 버전이 나온 뒤 조정한다. 첫 버전은 임시 수치로 진행할 수 있다.

## 게임의 형태

- 스틱아레나에서 탑다운 시점과 단순성을 가져온다. 캐릭터는 단색 면과 테두리로 이루어진 단순한 도형으로 표현한다.
- 헬다이버즈 2에서 협동 임무, 사망 후 증원, 장비 조합을 가져온다.
- 협동 PvE, 임무당 1~4명. PvP는 고려하지 않는다.
- 기본 진행은 장비 선택 → 투입 → 주·부목표 수행 → 탈출 → 결과 확인이다. 보상은 이후 확장 범위다.
- 첫 임무는 적 시설 파괴를 주목표로, 보급품 회수를 부목표로 삼고 지정 탈출 지점에서 일정 시간 버티는 형태다.
- 주 임무에 집중할 수 있도록 목표들을 한 임무 구역에 모은다. 먼 곳에 목표를 흩어놓아 이동을 강요하지 않는다.
- 보통 한 임무를 약 10분 동안 플레이하는 것을 상정한다. 10분이 고정된 즉시 종료 시각으로 확정된 것은 아니다.
- 첫 버전은 PC 브라우저 플레이면 충분하다. 설치형 Unity 클라이언트는 필요하지 않으며 모바일 지원은 이후로 미룬다.

## 서버 권위와 클라이언트

- 서버가 게임 시뮬레이션과 최종 판정을 수행한다.
- 가장 중요한 이유는 치트 방지다. 일관된 판정과 상태 동기화도 중요하다.
- 서드파티 클라이언트를 허용한다. 공식 클라이언트는 실제 게임을 플레이할 수 있는 구현이다.
- 공식 클라이언트에서만 작동하는 조준선 흔들림 같은 페널티를 게임 규칙으로 삼지 않는다.
- 입력과 동작이 허용되는지는 서버가 판단한다. 클라이언트가 주장하는 위치, 피해, 자원, 보상을 그대로 신뢰하지 않는다.
- 방지 대상으로 순간이동, 이동속도 조작, 무적, 탄약·공격력 조작, 보상 위조, 숨겨진 적의 현재 위치 노출을 지정했다.
- 오토에임 대응은 현재 관심 범위에서 제외했다. 모든 UI·입력 자동화 차이를 제거한다는 보장은 합의하지 않았다.

## 전투와 물리

- 마우스 방향을 입력받아 사격한다.
- 정밀 조준이나 클라이언트의 반동 조작을 요구하는 전투는 원하지 않는다.
- 구르기, 다이빙은 필요하지 않으며 고저차도 현재 범위에 포함하지 않는다.
- 날아가는 탄환, 폭발, 밀려남, 장애물 충돌, 엄폐, 지형 파괴를 원한다.
- 지형 파괴는 2D 벽·장애물을 부숴 통로를 여는 수준이다. 지면을 깎는 표현이나 파편의 충돌 판정은 필요하지 않다.
- 아군 사격으로 사망할 수 있다.
- 적 규모는 가능한 크게 만들고 싶다. 보장할 개체 수나 성능 수치는 아직 정하지 않았다.
- 맵 크기에는 강한 선호가 없다.

## 시야와 표현 성능

- 시야는 팀 전체가 공유한다.
- 서버가 숨겨진 적의 현재 위치를 보내지 않도록 설계한다.
- 고성능 기기라는 이유로 시야 범위를 늘리는 방식은 원하지 않는다.
- 허용된 시야 안의 적은 가능한 한 모두 표시한다. 기기 성능이 부족하면 가까운 적부터 표시한다.
- 클라이언트가 표시를 생략하더라도 서버의 적과 공격 판정은 계속 존재한다.
- 캠프는 시야가 밝혀져 있고, 동료 근처는 해당 동료가 확보한 만큼의 시야가 있다.
- 탐험한 지형의 기억, 캠프 시야의 정확한 범위·지속 조건은 미정이다.

## 사망, 증원, 임무 실패

- 증원 횟수는 무제한이다. 다른 플레이어가 증원을 호출하는 절차 없이 복귀한다.
- 최초 참가·난입·사망 후 증원은 모두 같은 5초의 투입 준비 시간을 적용한다.
- 증원 위치를 선택하지 않으면 자동으로 캠프에 투입하지 않고 계속 보류한다.
- 사망 시 장비를 떨어뜨리지 않는다.
- 증원 시 체력·탄약·수류탄 등은 초기 세팅과 동일한 상태로 복원한다.
- 증원 위치는 임의로 선택할 수 있다. 위치를 선택하는 과정에서 새로운 시야를 제공하지 않는다.
- 알려지지 않은 위험한 위치에 증원해서 죽는 것은 허용되는 결과다.
- 기본 증원 보호는 없다. 향후 아이템이나 로드아웃의 효과로 제공할 수는 있다.
- 팀 전원이 사망하면 임무가 실패한다. 솔로는 한 번 사망하면 실패한다.
- 10분마다 모든 플레이어에게 회피 불가능한 피해가 적용되며, 회차마다 피해가 강해진다. 캠프도 예외가 아니다. 그 피해로 전원이 사망하면 임무를 강제로 실패 처리한다.
- 구현 시 전멸·실패 판정을 증원 처리보다 먼저 수행하는 것으로 해석한다.
- 유효한 증원 좌표와 주기적 피해의 수치는 구현 기본값으로 정한다.
- 소총 예비탄 무한과 집중된 목표 배치를 바탕으로 우선 플레이한다. 고의 사망 억제를 위한 별도의 추가 페널티는 첫 버전에 도입하지 않는다.

## 장비와 보상

- 장비 구성은 주무기, 보조무기, 패시브다.
- 예시는 소총, 수류탄, 이동속도 증가 또는 체력 증가 패시브다.
- 로드아웃에 들고 갈 수 있는 예산을 두는 구상이 있었으나 세부 설명은 완료되지 않았다.
- 사용자는 이후 로드아웃 간 밸런스를 미루고 플레이 가능한 버전을 먼저 만들기로 했다.
- 소총에는 탄창과 재장전이 있으며 예비탄은 무제한이다.
- 재장전은 증원 준비 시간인 5초보다 짧아야 한다. 초기 구현값은 2초다.
- 수류탄은 소모품이다. 체력과 수류탄은 보급품으로 보충한다.
- 슬롯별 개수와 예산의 첫 버전 적용 방식, 구체적인 수치는 미정이다.
- 첫 버전에는 장비 해금과 계정 성장이 없다. 보상도 현재 구현할 대상이 없으며, 보상 배분에 따른 성공 기준의 차이는 우선순위가 낮다.

## 참가와 연결 복구

- 회원가입·로그인 없이 게스트로 접속한다.
- 방 코드로 초대할 수 있다.
- 진행 중인 임무에 새로운 플레이어가 참가할 수 있어야 한다.
- 늦게 참가했다는 이유로 새 플레이어에게 불이익을 주고 싶지 않다.
- 연결이 끊긴 플레이어는 재접속할 수 있어야 한다.
- 재접속 시 기존 캐릭터 상태를 복구하는 방식, 연결이 끊긴 동안의 캐릭터 처리, 자리 예약 시간은 구현 제안 단계다.

## 기술과 운영: 선호와 제안

- 사용자 선호: C# 가능, Linux 서버, 브라우저 플레이, 모바일은 이후 지원.
- GKE를 희망한 이유는 사용 경험이 있기 때문이다. GKE만 사용해야 한다는 요구는 아니다.
- 첫 구현은 독립 C#/.NET 게임 서버와 TypeScript/PixiJS 브라우저 클라이언트로 구성하고, 클라이언트 통신 규격을 문서화한다.
- 첫 버전은 브라우저 클라이언트만 제공한다.
- 기존 프로젝트 자료나 코드는 전달되지 않았다. 이 저장소에서 브라우저와 C# 서버의 첫 프로토타입을 새로 구현한다.
- 예상 동시접속자, 서버 예산, 배포 시점은 미정이다.

## 아직 정할 세부 사항과 현재 제안

아래는 사용자가 답하기 쉽게 만든 초안이며, 확정된 요구사항이 아니다. 수치 조정 자체가 첫 플레이를 지연시키지 않도록 한다.

| 항목 | 현재 제안 |
| --- | --- |
| 맵 | 고정 맵 하나로 시작 |
| 초기 적 | 접근해 공격하는 적과 원거리 공격하는 적으로 시작 |
| 생존 중 보급 | 체력·수류탄 보급품을 임무 구역에 배치 |
| 증원 대기 | 위치 미선택이면 계속 보류. 초기 구현은 위치 확정 후 5초 준비하고 투입 |
| 최초 참가 | 신규 플레이어는 초기 장비와 자원으로 투입; 사망 횟수에 따른 개인 페널티를 물려주지 않음 |
| 재접속 | 서버가 발급한 복구 토큰으로 기존 참가자를 식별하고 캐릭터·자원·사망·증원 상태를 이어받음 |
| 연결 끊김 | 초기 구현은 입력을 멈추고 피격 가능한 캐릭터와 자리를 120초 유지. 임무 시간 계속 진행 |
| 성공 | 주목표 완료 후 한 명 이상 탈출하면 팀 성공이라는 임시안을 사용 가능 |
| 정기 피해 | 임무 시작 시각을 기준으로 주기와 피해 회차를 관리; 참가·재접속으로 시간을 초기화하지 않음 |

## 증원과 신규 참가에 관한 설계상의 한계

- 자유로운 증원 위치와 초기 자원 복원을 유지하면 사망에 이동·보급 효과가 생긴다. 대기 시간과 보급 배치로 이점을 줄일 수 있지만 완전히 없어지는 것은 아니다.
- 최초 참가·난입·사망 후 증원에 공통 5초 투입 준비 시간을 적용한다.
- 재접속을 신규 참가와 구분하면 일반적인 연결 끊기·다시 연결하기로 자원을 초기화하는 문제를 막을 수 있다.
- 인증 없는 게스트가 기존 복구 토큰을 버리고 새 신분으로 참가하는 경우, 서버에 같은 사람임을 확실히 증명할 수단은 없다. 복구 토큰만으로 이 문제까지 해결했다고 주장하지 않는다.
- 서버 권위로 강제할 수 있는 게임 규칙과, 서로 다른 게스트가 실제로 같은 사람인지 판별하는 문제를 구분한다.

## 첫 플레이의 확인 기준 초안

- 브라우저 여러 개에서 같은 임무에 접속하고, 1~4명으로 한 판을 진행할 수 있다.
- 장비 선택, 이동과 사격, 적과의 전투, 목표 수행, 탈출 또는 실패가 한 흐름으로 연결된다.
- 사망·증원·전멸 규칙과 아군 사격이 모든 플레이어에게 일관되게 적용된다.
- 진행 중인 임무에 난입할 수 있고, 연결 복구 후에는 기존 참가 상태가 이어진다.
- 서버가 허용하지 않은 위치·공격·자원 상태를 클라이언트 입력으로 확정할 수 없다.
- 팀 시야로 공개되지 않은 적의 현재 위치가 클라이언트로 전송되지 않는다.
- 정확한 성능 목표는 최소 플레이가 구현된 뒤 부하 측정으로 정한다.
