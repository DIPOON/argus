# Argus 요구사항

마지막 갱신: 2026-10-10. 현재 합의와 첫 구현 범위를 기록한다. 전투의 확정 규칙 및 시험 수치는 [근접 RPS 전투](combat.md)에 상세히 기록한다.

## 목표

- 실제로 플레이할 수 있는 1~4인 협동 PvE 게임을 완성한다. 혼자서도 진행할 수 있다.
- 기반부터 직접 만드는 Veritas와 달리 Argus는 완성 속도를 우선한다. 기존 엔진·라이브러리·데이터베이스 사용이 가능하다.
- 게임 서버 개발 경험과 치트 방지가 중요하다. C# 서버, Linux 운영, PC 브라우저 클라이언트로 시작한다.
- 설치형 Unity 클라이언트와 모바일, PvP, 계정 성장·장비 해금·보상은 첫 범위에서 제외한다.
- 사용자는 C#을 배우고 있어 명시적 타입, 일반 생성자, 기본 for/foreach와 if/else를 선호한다. [AGENTS.md](../AGENTS.md)를 따른다.

## 게임과 임무

- 스틱아레나의 탑다운 시점과 단순함, 헬다이버즈 2의 협동 임무·증원·장비 구성을 출발점으로 삼았다.
- 현재 주 전투는 근접 타격·받아치기·잡기의 실시간 RPS다. 사격 중심의 이전 요구는 이 합의로 대체됐다.
- 면과 테두리 중심의 단순한 캐릭터. 고저차·구르기·다이빙은 첫 범위에 없다.
- 장비 선택 → 투입 → 주·부목표 → 탈출 → 결과. 목표는 한 구역에 모아 배치한다.
- 첫 임무는 시설 3곳 파괴, 선택 보급품 2개 회수, 탈출 구역 20초 확보다.
- 첫 맵은 1티어 일반 적만 배치·추가 생성한다. 2티어 적은 등장하지 않으며, 선딜은 기존의 두 배(타격 1.7초, 방어·잡기 1.9초)로 늘려 기본 대응을 익히게 한다.
- 약 10분 임무를 목표로 하지만 10분에 즉시 종료되는 고정 규칙은 아니다.
- 벽·장애물 충돌과 벽 파괴를 유지한다. 파편 충돌과 지면을 깎는 표현은 필요하지 않다. 탄환·폭발·밀려남은 향후 해당 기술을 추가할 때 다시 적용할 수 있다.

## 현재 전투의 핵심

- 타격 < 방어 < 채널 < 타격. 기본 채널은 근거리 잡기다.
- 타격·방어·채널 각 한 슬롯과 자유 한 슬롯, 총 네 슬롯. 별도 기본 사격은 없다.
- 기본 받아치기는 전방 방어 후 일반 반격. 빈 방어 뒤에도 반격하며, 상성 패배 시에는 취소한다. 마나 회복은 없다.
- 기본 잡기는 한 동작 동안 유지되며 단일 대상이다. 타격·반격은 좁은 범위다. 기술 중 이동이 가능하다.
- 일반 적과의 승리: 적 처치. 비김: 서로 피해 1. 패배: 플레이어 피해 1, 적 생존.
- 무행동인 적에게는 일반 피해 1. 적의 예고에는 이미 해당 상성이 있다.
- 2티어는 동시에 유효한 대응 두 개가 필요하다. 동료와 겹쳐 합산할 수 있다. 같은 소유자의 독립 기술도 소유자가 같다는 이유로 제외하지 않는다.
- 완전 파훼는 체력과 무관한 처치이며 같은 공격 범위의 무행동 동료도 보호한다. 엘리트의 1티어 행동을 파훼해도 처치한다.
- 엘리트는 기술별 티어와 부분 대응 효과, 행동 구성, 외형의 변형을 가진다. 체력 감소가 티어 감소를 강제하지 않는다.
- 아군 피해 없음. 아군끼리는 겹칠 수 있고 적끼리 및 플레이어–적은 몸 충돌한다.
- 마나 자연 회복 없음. 투입 마나 0, 보급 상자로 보충, 빗나가도 사용 비용을 지불한다. 회복 기술은 이후 별도 슬롯 기술로 추가할 수 있다.
- 기존 총기·수류탄·터렛·패시브 구성은 이번 네 슬롯의 기본기 버전으로 대체했다. 정교한 장비 밸런스와 예산은 이후 단계다.

## 서버 권위와 시야

- 서버가 위치·시간·접촉·상성·피해·마나·증원·임무 상태를 계산한다. 클라이언트는 이동 방향·조준 방향·슬롯 입력을 보낸다.
- 순간이동, 이동속도·무적·자원·피해 조작, 숨겨진 적의 현재 위치 노출을 막는다. 보상은 아직 구현 대상이 없다.
- 서드파티 클라이언트를 허용한다. 공식 클라이언트에서만 동작하는 반동이나 조준선 흔들림으로 규칙을 강제하지 않는다.
- 입력 자동화나 오토에임 차이를 모두 없앤다는 보장은 없다.
- 캠프와 생존 동료의 시야를 팀 전체가 공유한다. 대기·사망·투입 위치 선택은 새 시야를 주지 않는다.
- 시야 밖의 적은 위치·기술 예고를 직렬화 전에 제외한다. 효과도 위치에 따라 필터링한다.
- 맵 구조·벽 파괴·시설·보급·목표 진행은 공개 정보다.
- 성능이 부족한 클라이언트는 허용된 시야 안의 가까운 적부터 표시를 줄일 수 있다. 서버 판정은 계속 진행한다. 고성능 기기의 시야 범위가 넓어지는 규칙은 없다.

## 증원과 접속

- 최초 투입·난입·사망 후 증원 모두 위치 확정 후 5초. 위치 미선택이면 계속 대기한다.
- 임의의 유효한 위치를 선택할 수 있으며 기본 무적은 없다. 알 수 없는 위험한 곳으로 투입해 죽는 것은 허용된다.
- 사망 시 장비를 떨어뜨리지 않는다. 증원 시 최초 장비와 체력, 마나 0을 복원한다.
- 다른 생존자가 있으면 증원 횟수는 무제한이다. 전원 사망하면 실패하며 대기 중 증원이 이를 되돌리지 않는다. 솔로는 첫 사망에 실패한다.
- 임무 시작부터 10분마다 캠프를 포함한 모든 생존자에게 회피 불가능한 증가 피해를 준다. 난입·재접속으로 타이머를 초기화하지 않는다.
- 게스트 참가, 6자리 방 코드, 진행 중 난입, 같은 탭 새로고침 복구를 지원한다.
- 서버 발급 비밀 토큰으로 기존 참가자를 식별한다. 연결 끊김 뒤 120초간 피격 가능한 몸과 자리를 유지하며, 입력은 중단한다.
- 재접속은 체력·마나·장비·기술 시간·사망·투입 상태를 초기화하지 않는다. 같은 토큰의 새 연결은 이전 연결을 교체한다.
- 토큰을 버린 새 게스트를 동일인으로 판별하지는 못한다.

## 운영과 검증 범위

메모리 기반 단일 C# 서버와 TypeScript/PixiJS 브라우저 클라이언트다. 서버 재시작 후 상태 복구, 영구 저장, 보상, 공개 서비스 인증은 없다. GKE는 사용 경험 때문에 선호하며 강제 요구가 아니다. 여러 서버에 걸친 방 배정·연결 라우팅·종료 절차·부하 검증은 배포 확장 시 필요하다.

방 상한과 적 상한은 수치 설정이며 부하 보장값이 아니다. 실제 확인한 내용은 [검증 기록](verification.md)에 기록한다. 새 전투 규칙은 [protocol v2](protocol.md)로 제공한다.
