- `dotnet run --project tests/Argus.Server.Tests`: 14/14 통과.
- `npm --prefix client run build`: TypeScript 검사 및 프로덕션 빌드 통과.
- `npm --prefix client run test:e2e`: 3/3 통과, 56.1초.
- 실제 브라우저의 로비·전투 스크린샷을 확인했다. 출력은 `client/test-results/`에 있으며 Git에 포함하지 않는다.

서버 검사는 입력 순서·속도·발사 간격·탄약·2초 재장전, 5초 투입과 위치 미선택 대기, 아군 피해, 엄폐·벽 파괴·폭발 밀려남, 팀 시야와 전송 제외, 전멸 우선 판정, 주기적 피해, 보급·탈출, 복구 토큰과 4인 제한을 포함한다.

브라우저 검사는 서로 다른 sessionStorage를 쓰는 네 탭의 참가·투입·이동·사격·재장전·새로고침 복구를 확인한다. 별도 통신 검사는 상태 위조, 잘못된 입력, 잘못된 복구 토큰, 다섯 번째 참가, 같은 토큰으로 연결 교체 시 이전 소켓의 4001 종료를 확인한다. 실제 임무 검사는 공개된 입력만 사용하는 네 대원으로 시설을 파괴하고 탈출 성공을 확인한다. 서버 상태를 바꾸는 테스트 전용 HTTP API는 없다.

테스트 분대는 적을 자동 조준하고, 시설 완료 후 탈출 구역으로 이동하며, 필요하면 증원을 요청한다. 짧게 완료한 자동화 시나리오는 사람의 평균 임무 시간이나 난이도 측정이 아니다.

이 환경의 소프트웨어 WebGL로 여러 화면을 동시에 렌더링할 때 초기화 지연이 발생했다. 최종 통합 검사는 Chromium의 WebGL을 비활성화해 실제 제품에 포함된 Canvas 대체 경로를 사용했다. 하드웨어 WebGL의 다중 클라이언트 성능, 적 180마리의 프레임 유지, 최대 방 수의 서버 부하는 별도 측정이 필요하다.

Docker Desktop의 WSL 연동이 없어 Docker 이미지 빌드는 실행하지 못했다. GKE를 포함한 클라우드 배포는 수행하지 않았다. 프로토타입은 메모리 기반 단일 프로세스이며 서버 재시작 시 진행 중인 작전이 사라진다.

추가 서버 검사는 잘못된 장비의 원자적 거절, 장비별 탄창·재장전·발사 간격, 산탄 개수와 퍼짐·짧은 사거리, 관통의 거리 순서·3명 제한·동일 적 중복 피격 방지·벽과 아군 차폐를 포함한다. 탄환의 마지막 이동 구간도 남은 사거리로 제한하는지 확인했다.

터렛은 설치 위치·대기 시간·소유자당 한 기·교체·만료, 숨겨진 적을 노출하거나 공격하지 않는지, 팀 시야 확보 후 사격, 소유자 피격을 포함한 아군 피해, 적의 터렛 공격, 탄환·폭발에 의한 파괴, 증원 후 교체와 소유자 이탈 정리를 확인했다. 재접속은 선택 장비와 자원을 유지한다.

추가 브라우저 검사는 로비의 산탄총·터렛 선택, 서버의 장비 상태, HUD 탄창 표시, G 설치, 재설치 대기 중 요청 거절, 재장전, 새로고침 후 터렛·대기 시간 유지, 다음 작전에서 관통총·수류탄 선택을 확인한다. 기존 네 대원의 실제 임무 완료도 다시 통과했다.

브라우저 검사는 앞선 검증과 같은 Canvas 대체 경로를 사용했다. 장비 간 승률·반복 플레이 의향·최대 방 수의 부하는 측정하지 않았다. 피해·사거리·터렛 수명은 플레이 후 조정할 초깃값이다.
